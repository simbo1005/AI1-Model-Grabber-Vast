## Preserve the existing environment

The three new tiles use a separate, pinned ComfyUI checkout and Python environment:

| Component | Isolated runtime |
| --- | --- |
| ComfyUI | `e9afbccc2669677076feb08e52658f129cd8c12b` |
| Python | 3.12 |
| PyTorch | 2.10.0+cu130 |
| torchvision / torchaudio | 0.25.0+cu130 / 2.10.0+cu130 |
| Attention | PyTorch SDPA |
| Host requirement | NVIDIA driver 580 or newer, functional CUDA GPU access |

The existing pipelines keep their original ComfyUI, CUDA 12.8 Torch, SageAttention 2.2 wheel, graph guard and SNN-KRAST warmup. No existing workflow JSON is rewritten. The provider-specific CRT pins, ports, Jupyter integration, private-model references and added DSNN resources stay intact.

The isolated runtime lives at `<ComfyUI parent>/.dsnn-runtimes/minimax-h3-cu130/`. Its models link to the existing model directory; input/output directories are shared. Its Python packages, custom nodes and user metadata are separate. First setup downloads additional software wheels and needs disk space for that environment, but does not duplicate model weights. Native SageAttention is not transplanted into CUDA 13.

A small middleware bridge in native ComfyUI forwards HTTP and WebSockets to the selected worker on loopback port 18189. Public ComfyUI URLs and exposed ports do not change. Switching requires an idle queue, blocks new submissions during the switch, and preserves queued/running jobs. A failed worker activation restores the native selection. Switching back to an existing tile stops only the managed worker. An occupied private port or a modified managed bridge is left untouched with an explicit error.

Manager security is unchanged. Impact Pack's unpinned SAM2 requirement is resolved to reviewed commit `2b90b9f5ceec907a1c18123530e92e794ad901a4` in a temporary requirements file; the node checkout is preserved. Installed Torch/CUDA ABI packages remain constrained during node installation.

## Credentials and NVIDIA VFX

Use your template's `HF_TOKEN` and `CIVITAI_TOKEN`. No upstream embedded Civitai credentials are imported. Civitai links use the canonical official host and retain the intended file selection.

The NGX helper resolves linker aliases correctly and, when necessary, downloads/extracts only the userspace library matching the running NVIDIA driver. It never installs or replaces GPU drivers. If the configured Ubuntu repositories cannot provide that exact library, setup explains the mismatch instead of changing the driver. NVIDIA VFX features still depend on their supported GPU/driver combination.

## Preview images and validation

Use RunPod `sdcioba/comfyui-workflow-launcher:2.5-test`, or Vast `ghcr.io/simbo1005/comfyui-workflow-launcher-vast:1.5-test` (also Docker Hub `sdcioba/comfyui-workflow-launcher-vast:1.5-test`). Existing published tags are retained.

The new tiles require the baked runtime bridge in these images; updating launcher files alone cannot add it. Their package setup, node installation and CPU-compatible registration checks run in Linux CI before image publication. Regression tests cover HTTP/binary/WebSocket proxying, origin guard preservation, queue refusal, recovery/rollback, provider catalog preservation and unchanged HF/Civitai transfer functions. GPU-only node registration and actual model generation require a GPU instance; CPU checks do not certify kernel performance or generation quality.

Runtime diagnostics appear in the launcher's diagnostics API. The isolated worker log is `.dsnn-runtimes/minimax-h3-cu130/comfyui.log` beside the native ComfyUI directory.
